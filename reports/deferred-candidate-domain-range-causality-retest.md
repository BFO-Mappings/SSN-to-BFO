# Deferred Candidate Domain/Range Causality Retest

## Scope

This report tests whether locally asserted `rdfs:domain` / `rdfs:range` fallback axioms in `SSN2BFO.ttl` caused previously deferred or rejected object-property candidate mappings to become HermiT-unsafe. It uses the current full local SOSA closure profile and temporary graphs only. No tracked ontology, workbook, import, tool, example, release, generated artifact, or existing report is edited.

The controlling question is: for each deferred or rejected candidate mapping, does the candidate remain HermiT-unsafe after removing only the locally asserted `rdfs:domain` and `rdfs:range` axioms for the relevant source property?

## Graph Construction

Each HermiT graph loaded:

- `imports/cco.ttl`
- `imports/sosa.ttl`
- `imports/ssn.ttl`
- `imports/ssn-systems.ttl`
- a temporary `SSN2BFO.ttl` variant under `/tmp`

Then the graph removed all `owl:imports` triples and the established sample simplicity blockers:

- `sosa:isSampleOf rdf:type owl:FunctionalProperty`
- `sosa:hasSample rdf:type owl:InverseFunctionalProperty`

HermiT command used for each variant:

```bash
robot reason --reasoner HermiT --input <variant.ttl> --output <variant-reasoned.ttl>
```

Temporary graph directory: `/tmp/ssn-to-bfo-deferred-candidate-domain-range-causality-retest`. The graph path for each run is shown explicitly in the result tables. The sample simplicity blocker did not reappear in any run.
