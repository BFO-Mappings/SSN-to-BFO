# Prior Decision Audit Against Full SOSA Closure

## Scope

This report audits prior project decisions after the repository materialized the indirect SOSA import as:

```text
imports/sosa.ttl
```

No ontology mappings, workbook rows, imports, tools, examples, generated/release artifacts, or existing reports were edited for this audit.

The audit question is narrow: which prior decisions depended on the older reduced M2 HermiT graph, and which decisions need relabeling, rerun, or replacement by full local SOSA closure evidence?

## Import Closure Shift

The project previously used a reduced M2 diagnostic graph built from:

```text
imports/cco.ttl
imports/ssn.ttl
imports/ssn-systems.ttl
SSN2BFO.ttl
```

The newer full local SOSA closure graph is built from:

```text
imports/cco.ttl
imports/sosa.ttl
imports/ssn.ttl
imports/ssn-systems.ttl
SSN2BFO.ttl
```

Both graph profiles remove all `owl:imports` triples and the established sample simplicity blockers:

```ttl
sosa:isSampleOf rdf:type owl:FunctionalProperty .
sosa:hasSample rdf:type owl:InverseFunctionalProperty .
```

The import structure now visible locally is:

| File | Import structure |
|---|---|
| `SSN2BFO.ttl` | directly imports `http://www.w3.org/ns/ssn/`, `http://www.w3.org/ns/ssn/systems/`, and local CCO target resolved from the CCO import IRI |
| `imports/ssn.ttl` | imports `sosa:` |
| `imports/ssn-systems.ttl` | imports `ssn:` |
| `imports/sosa.ttl` | local materialized SOSA source file now exists |

The reduced M2 graph omitted the materialized indirect SOSA import. That omission matters most for SOSA inverse-property and object-property context, especially around `sosa:madeActuation` / `sosa:madeByActuator`.

## Audit Rule

This audit applies the following rule.

Reduced-M2 HermiT failures generally remain useful as evidence that a mapping is unsafe in at least one profile, but explanations may change under full closure.

Reduced-M2 HermiT clean results do not establish full-SOSA-closure safety. Any such result should be rerun if it was used to justify keeping an active mapping or adding a new active mapping.

ELK instance-entailment results remain useful as coverage and regression checks, but they must not be treated as full-closure HermiT consistency evidence.

Spreadsheet/TTL audit decisions are mostly unaffected unless they used imported SOSA axioms as mapping evidence.

## Tooling Inspection

### `tools/test_elk_instance_mapping_entailments.py`

The default merged graph for each ELK example is built from:

```text
imports/cco.ttl
imports/ssn.ttl
imports/ssn-systems.ttl
SSN2BFO.ttl
```

It does not include `imports/sosa.ttl` by default.

The report generated by the tool explicitly says the test is not full OWL DL reasoning and not HermiT. It intentionally ignores inverse-property reasoning, many restriction forms, and other full-OWL behavior.

Conclusion: the ELK instance mapping entailment test is still useful, but it is reduced/import-limited unless invoked with an explicit extra mapping input. It should either be updated to include `imports/sosa.ttl` where appropriate, or its generated scope text should be updated to label the default as reduced/import-limited.

It does not include `imports/sosa.ttl` by default.

The tool is a lightweight parse/RDFS-closure smoke test, not a full OWL DL or HermiT validation.

Conclusion: this smoke test is useful as an instance-data regression check, but it is not full local SOSA closure evidence.

### `tools/run_validation_suite.py`

The standard suite currently runs:

```text

```

It does not include a full local SOSA closure HermiT check.

Conclusion: standard validation passes, but standard validation currently does not prove that the full local SOSA closure graph is HermiT-clean. The project should add a dedicated full-closure HermiT gate.

## Key Affected Decisions

The most affected decision family is the `madeByActuator` / `madeActuation` area. Prior reduced-M2 reports framed the issue around explicit `sosa:madeByActuator rdfs:range sosa:Actuator` or proxy inverse behavior. Full local SOSA closure showed the baseline itself was inconsistent before adding that explicit range axiom, because the materialized SOSA import contributes inverse/object-property context and related source axioms.

The source domain/range operationalization decisions are also affected. The current active source-level domain/range set may be safe after the paired actuation-agent deferral, but the historical proof for the 55 added axioms was reduced-M2. The current full-closure clean result after the actuation-agent deferral is encouraging, but the project should make that check part of validation rather than relying on one report.

The reactivation-canary summaries for SSN Systems dependence, Input/Output, and `observedProperty` remain useful because their failed reactivations show risk in reduced M2. However, they should not be treated as final full-closure explanations.

## Key Unaffected Decisions

Spreadsheet/TTL audit mechanics remain valid. The two expected `sosa:Sensor` version-alignment issues are separate from HermiT import-closure fidelity.

The ELK and instance-data reports remain valid as regression and coverage artifacts. Their limitation is interpretive: they are not full-closure HermiT checks.

Rationale cleanup decisions, such as rejecting the old `ssn:hasInput` / `ssn:hasOutput` CCO mappings as intended-but-deferred mappings, remain unaffected by the materialized SOSA import.

## Recommendation

The next branch should be:

```text

```

That branch should add a standard validation or workflow check that builds the full local SOSA closure graph, removes the same imports/sample cleanup triples used in the reports, runs ROBOT/HermiT, and fails if any unsatisfiable classes appear.
