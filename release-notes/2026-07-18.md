# Included products

- `SSN2BFO.ttl` - SSN-to-BFO Integrated Mapping. Directly asserts the complete governed COMS axiom set for the SSN/SOSA alignment with BFO and CCO.
- `current-ssn-sosa/ssn-sosa-alignment-core.ttl` - SSN/SOSA Alignment Core. Directly asserts the governed target-neutral SSN/SOSA alignment axioms shared by the modular products and imports no ontology.
- `current-ssn-sosa/ssn-sosa-bfo-mapping.ttl` - SSN/SOSA Strict BFO Mapping. Directly asserts governed BFO-bearing axioms without weakening and imports the alignment core.
- `current-ssn-sosa/ssn-sosa-bfo-projection.ttl` - SSN/SOSA BFO Projection. Imports the strict BFO mapping and is the designated location for future approved weaker but sound BFO consequences; it currently asserts no direct projection axiom.
- `current-ssn-sosa/ssn-sosa-cco-extension.ttl` - SSN/SOSA CCO Extension. Directly asserts governed CCO-bearing and mixed BFO/CCO axioms unchanged and imports the strict BFO mapping.

# Product selection guidance

Use `SSN2BFO.ttl` when the complete governed mapping is needed in one ontology. Use the alignment core for target-neutral SSN/SOSA alignment axioms. Use the strict BFO mapping for governed BFO-bearing axioms without CCO-extension content. Use the BFO projection only when the designated import-only projection layer is required; it contains no direct projection axioms. Use the CCO extension for governed CCO-bearing and mixed BFO/CCO axioms.

Run these commands from a clean checkout after this notes file is committed. The `SOURCE_COMMIT` value is the exact committed revision recorded in the governed manifest.

```sh
SOURCE_COMMIT="$(git rev-parse HEAD)"

PYTHONDONTWRITEBYTECODE=1 python -B tools/rehearse_release.py verify \
  --release-id 2026-07-18 \
  --release-date 2026-07-18 \
  --git-tag v2026-07-18 \
  --source-commit "${SOURCE_COMMIT}" \
  --notes release-notes/2026-07-18.md
```

Construct and validate an ephemeral formal package at an absent, external path:

```sh
SOURCE_COMMIT="$(git rev-parse HEAD)"
WORK_ROOT="$(mktemp -d)"
PACKAGE_PARENT="${WORK_ROOT}/releases"
PACKAGE_DIR="${PACKAGE_PARENT}/2026-07-18"
ARCHIVE_DIR="${WORK_ROOT}/archive"
mkdir -p "${PACKAGE_PARENT}"
trap 'rm -rf "${WORK_ROOT}"' EXIT

PYTHONDONTWRITEBYTECODE=1 python -B tools/build_release.py \
  --release-id 2026-07-18 \
  --release-date 2026-07-18 \
  --source-commit "${SOURCE_COMMIT}" \
  --git-tag v2026-07-18 \
  --notes release-notes/2026-07-18.md \
  --output-dir "${PACKAGE_DIR}"

PYTHONDONTWRITEBYTECODE=1 python -B tools/check_release.py validate \
  --package-dir "${PACKAGE_DIR}"

PYTHONDONTWRITEBYTECODE=1 python -B tools/release_archive.py build \
  --package-dir "${PACKAGE_DIR}" \
  --output-dir "${ARCHIVE_DIR}" \
  --release-id 2026-07-18 \
  --source-commit "${SOURCE_COMMIT}"

PYTHONDONTWRITEBYTECODE=1 python -B tools/release_archive.py validate \
  --package-dir "${PACKAGE_DIR}" \
  --archive "${ARCHIVE_DIR}/SSN2BFO-2026-07-18.tar" \
  --sidecar "${ARCHIVE_DIR}/SSN2BFO-2026-07-18.tar.sha256" \
  --release-id 2026-07-18 \
  --source-commit "${SOURCE_COMMIT}"
```

Creating the proposed Git tag and creating a GitHub release are separate, human-gated actions and are not performed by these commands.
